## Enforcement matrix

Not every control carries the same weight on every tool. This table states
honestly what is machine-enforced on **Claude Code** vs. advisory:

| Control | Enforcement on this tool |
|---------|--------------------------|
| Block destructive folder deletes | **BLOCKING** — runs automatically via `.claude/settings.json` |
| Block dropping / truncating tables | **BLOCKING** — runs automatically via `.claude/settings.json` |
| Block force-push to shared history | **BLOCKING** — runs automatically via `.claude/settings.json` |
| Evoke audit trail (observability) | **NON-BLOCKING (audit)** — records tool calls to `.agent/logs/*.jsonl`; it observes, it never prevents |
| Discovery before code | **ADVISORY** — the `discovery` agent is available, but nothing makes it run first |
| Rules / working agreement | **ADVISORY** — instruction-file prose; the model is steered, not blocked |
| Operating procedure (plan → verify → commit) | **ADVISORY** — becomes blocking only when the git pre-commit gate is installed |

An observability control records; it never prevents.
The trace records tool calls that ran. A call refused by a guardrail or by
your permission prompt produces no PostToolUse record.

An advisory guardrail shapes behavior but cannot stop a determined agent.
Treat anything not marked BLOCKING as a convention your team still owns.
